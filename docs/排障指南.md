# 排障指南

> **只观测、不封禁、不改防火墙、不自动处置。**
> 本文只讲「怎么把问题说清楚、怎么把日志安全地交出来」，不涉及任何防护动作或规则修改。

外部用户报 BUG 时，最常见的是丢一句「打不开」加一张截图。定位这类问题需要环境、日志、状态三方面的信息，来回追问成本很高；而直接让人把 `config.json` 发过来又有地图密钥泄露风险。

这份文档把整套流程固化成两条通道 + 一份 6 件套清单。

---

## 一、最快的一条路：应用内一键导出

**设置 → 最底部 → 问题反馈 · 运行日志一键导出 → 「导出运行日志（已脱敏）」**

会下载一份 `ipsense-diag-<时间>.txt`，里面已经合并了：

- 主运行日志 `/var/log/apps/ipsense.log` 尾部
- 兜底副本 `$TRIM_PKGVAR/app.log` 尾部
- 生命周期日志 `$TRIM_PKGVAR/cmd.log` 尾部
- 应用版本 / 架构 / 环境变量
- `/api/health`、`/api/status`、`/api/sources` 的状态
- 数据源状态、归属库状态、数据库聚合计数
- 配置的**白名单脱敏版**

自动脱敏规则：地图 KEY / 令牌 / 口令 / 邮箱抹除；来访 IP 只保留前两段（例 `220.205.*.*`）；**不导出 `events.db` 原始事件行、不含原始日志全文**。

旁边还有「先在界面预览」，可以先自己扫一眼再决定要不要导出。

> 这份 `.txt` 就是 Issue 表单里 ③ 那一项，直接粘贴或作为附件上传即可。

## 二、命令行通道：`tools/diag_bundle.sh`

应用打不开、SSH 还能连上时，用脚本收集：

```sh
# 从仓库拿到脚本后，在设备上执行（输出目录可省略，默认当前目录）
sh tools/diag_bundle.sh /vol1/1000/分享
```

产物：`ipsense-diag-<时间戳>.tar.gz`。脚本全程**只读**：不改配置、不重启应用、不清理日志、不动数据库，每一步独立容错（文件缺失、应用没启动都会写明原因而不是中断）。

包内文件：

| 文件 | 内容 |
|---|---|
| `00-README.txt` | 脱敏说明与文件索引 |
| `10-env.txt` | 版本、架构、环境变量、socket 状态 |
| `20-main-log.txt` | 主运行日志尾部 |
| `30-fallback-log.txt` | 兜底副本尾部 |
| `40-cmd-log.txt` | 生命周期日志尾部 |
| `50-config-redacted.txt` | 配置（敏感键已剔除） |
| `60-health.txt` | `/api/health` / `/api/status` / `/api/sources` |
| `70-probe-status.txt` | `gateway.py probe` / `status` |
| `80-db-overview.txt` | `events.db` 体积与聚合行数（不含事件明细） |
| `90-files.txt` | 关键文件清单与大小 |
| `99-app-diag-export.txt` | 应用内 `/api/diag/export`（1.1.15+，最完整） |

脚本优先复用应用自带的 `diag.scrub()`；旧版本没有这个模块时，会回退到脚本内嵌的同规则脱敏实现。默认只回读每个日志尾部 400 行（`TAIL_N=400` 可覆盖）、单文件最多 2 MB。

> 脚本**不会替你上传或提交任何内容**，也不会删除临时目录（方便复核脱敏结果），确认无误后自行清理即可。

## 三、诊断 6 件套（Issue 必填）

| # | 项目 | 从哪来 |
|---|---|---|
| ① | **现象与时间** | 哪一类问题、具体做了什么、发生时间、界面选的时间范围（日志按时间检索，这项最关键） |
| ② | **版本与环境** | 应用版本、fnOS 版本、设备架构 / 安装包、安装方式（全新安装还是覆盖升级） |
| ③ | **运行日志诊断包** | 设置里的一键导出 `.txt`，或 `diag_bundle.sh` 的 `.tar.gz`（已脱敏） |
| ④ | **健康与状态** | `probe` / `status` / `/api/health` / `/api/status` / `/api/sources`（诊断包 60、70 两份文件） |
| ⑤ | **底图与数据源诊断** | 「设置 → 底图诊断」全部条目（可点「复制诊断信息」）+ 顶部状态标颜色 + 数据源列表状态 |
| ⑥ | **复现步骤与截图** | 1/2/3 步、界面截图、浏览器 Console / Network 里的红色报错；偶发问题写明频率与重启后是否恢复 |

缺任何一项通常都要再追问一轮。Issue 表单把这 6 项都设成了必填。

## 四、文件都在哪

| 用途 | 路径 |
|---|---|
| 主运行日志 | `/var/log/apps/ipsense.log` |
| 兜底副本 | `$TRIM_PKGVAR/app.log`，通常 `/vol1/@appdata/ipsense/app.log` |
| 生命周期日志 | `$TRIM_PKGVAR/cmd.log` |
| 配置文件 | `$TRIM_PKGVAR/config.json` |
| 事件数据库 | `$TRIM_PKGVAR/events.db`（配套 `events.db-wal` / `events.db-shm`） |
| PID 文件 | `$TRIM_PKGVAR/ipsense.pid` |
| Unix socket | `$TRIM_APPDEST/app.sock`，通常 `/var/apps/ipsense/target/app.sock` |
| 汇总日志 | `ipsense-summary-latest.md`（用户自选的保存目录） |
| 应用代码 | `$TRIM_APPDEST/`，通常 `/var/apps/ipsense/target/` |

`TRIM_APPDEST` / `TRIM_PKGVAR` 由 fnOS 在应用进程里注入，手工 SSH 执行时可能为空，需要显式设置：

```sh
export TRIM_APPDEST=/var/apps/ipsense/target
export TRIM_PKGVAR=/vol1/@appdata/ipsense
```

**关于 `events.db`**：它不是配置文件，是 SQLite 数据库（WAL 模式）。`events.db` / `events.db-wal` / `events.db-shm` 三者是一套，不要单独删除或只复制主库。默认保留 30 天，每小时清理一次超期记录。停掉应用后删掉三件套可以重置历史，但地图、排名、记录会全部清空。**排障时不需要交出这个文件**，诊断包里已经给了聚合计数。

**关于 `config.json`**：里面有明文地图 KEY。转发前至少删掉 `map_key` / `map_keys` / `map_custom` 三个键，以及 `home_ip` / `home_proxy_ip` 等出口 IP 字段。更省事的做法是直接交诊断包，别交原始配置。

**关于汇总日志**：那份 10 段 Markdown 是给 AI 分析态势用的，不含运行错误，**不能拿来排障**。

## 五、内置诊断抓手

```sh
export TRIM_APPDEST=/var/apps/ipsense/target
export TRIM_PKGVAR=/vol1/@appdata/ipsense

# 版本、路径、socket、Python 解释器、离线库是否就位
python3 "$TRIM_APPDEST/server/gateway.py" probe

# 进程与 socket 是否活着
python3 "$TRIM_APPDEST/server/gateway.py" status

# 直接打 Unix socket，绕开 Nginx 反代，判断是应用还是网关的问题
curl --unix-socket "$TRIM_APPDEST/app.sock" \
  http://localhost/app/ipsense/api/health
curl --unix-socket "$TRIM_APPDEST/app.sock" \
  http://localhost/app/ipsense/api/status
curl --unix-socket "$TRIM_APPDEST/app.sock" \
  http://localhost/app/ipsense/api/sources

# 1.1.15+：后端自行脱敏的完整诊断包
curl --unix-socket "$TRIM_APPDEST/app.sock" \
  http://localhost/app/ipsense/api/diag/export
```

前端侧还有三个不需要 SSH 的抓手：

- **顶部状态标**：三级语义 —— 全绿「运行中」/ 橙「部分数据异常」/ 红「连接失败」或「归属库异常」。鼠标悬停能看到本轮未响应的接口名。只有连续两轮接口全部无响应才会标红，一次抖动不会误报。
- **设置 → 底图诊断**：当前服务商、引擎 / 坐标系、SDK 地址、KEY 是否已配置、SDK 是否加载、容器尺寸、底图资源请求有无 4xx、弧线绘制条数、刷新间隔。旁边有「复制诊断信息」。
- **设置 → 归属信息源**：在线校验缓存命中数、各数据源状态；「批量校验高频 IP」/「订正历史归属」/ IP 画像里的「立即在线核验」。

其它可用接口与本地脚本：

| 入口 | 用途 |
|---|---|
| `/api/export?range=24h` | 导出当前范围的 CSV（含区级归属） |
| `/api/summary/status` / `/api/summary/download` | 汇总日志生成状态与下载 |
| `/api/geo/sources` / `/api/geo/detail?ip=` | 在线核验数据源状态与单 IP 裁决明细 |
| `tools/selftest.py` | 离线自检，覆盖历史版本回归 |
| `tools/smoke_arch.py` | 跨架构运行冒烟 |
| `tools/live_probe.py` | 真机接口探针 |

## 六、按症状查

| 症状 | 先看哪里 |
|---|---|
| **打不开 / 白屏** | `status` 与 `app.sock` 是否存在 → `cmd.log` → 主日志尾部 → Nginx 反代是否把 `/app/ipsense/*` 转进来；诊断包 60/70 两份会直接给出答案 |
| **没数据 / 不刷新** | `/api/sources` 里每一路是「已读取」还是「文件不存在 / 读取异常」→ 界面选的时间范围 → `/api/events` 的 `last_id` 是否在涨；状态标橙色时看悬停提示的接口名 |
| **底图不显示** | 「底图诊断」的 KEY 是否已配置 / SDK 是否已加载 / 底图资源请求有无 4xx。高德 KEY 无效、未绑定「Web 端 (JS API)」、域名白名单不含本站、未配 jscode 都会让服务端返回纯文本而不创建 `AMap`；正确域名是 `webapi.amap.com`。**底图失败只影响底图，采集与统计不受影响**，会自动回退到不绘国界的坐标散点示意 |
| **归属不准 / 缺区级** | IP 画像里点「立即在线核验（忽略缓存）」看 4 票明细；1.1.15 起新公网 IP 首次入库即进入后台核验队列，也可在设置里确认「新 IP 首次出现即自动核验」为开。区县免费源实测均不返回区县：1.1.16 起可在画像点「在线校验」复制 IP 到 `tool.hiofd.com/ip/` 核对，把「区」填回输入框保存；或在设置里配自定义区级接口自动补全 |
| **同省 / 境内来源看不见** | 1.1.15 起地域分布境内按省细分（不再归并成一个「中国」气泡），同省短弧也不再被近距阈值吞掉；若仍异常，检查 `/api/geodist` 返回的 `regions[].scope` 与热点里的 `province` |
| **弧线不显示 / 中断** | 1.1.16 起 SDK 折线统一收敛到 `[-180,180]` 合法经度并在 `±180` 边界分段（1.1.15 的 `±360` 世界副本会让腾讯 GL 整层拒绝渲染）；散点视图仍用本机中心 360° 连续窗口。诊断里可看「跨日期变更线」条数 |
| **卡顿 / 加载慢** | 「底图诊断」的地图重绘次数与最近耗时 → 设置里调大刷新间隔、减少每张地图弧线数量、关掉散点模式流动光点；画像明细已窗口化到最近 3000 条 |
| **汇总日志没生成** | `/api/summary/status` → 保存目录是否通过绝对路径 / 防穿越 / 真实目录 / 可写探针四层校验 → 原生文件夹选择器是否返回了路径。注意这份日志只用于交给 AI 分析，软件不会据此自动防护 |

## 七、隐私边界

诊断包和一键导出都遵循同一套规则：

- 配置先按键名剔除（`map_key` / `map_keys` / `map_custom` / 出口 IP / `ignore_ips` 等），再整体过一遍文本脱敏；
- 日志里的 KEY / 令牌 / 口令 / Bearer / 私钥块 / 邮箱全部抹除；
- IPv4 只保留前两段，IPv6 整体替换，避免导出完整来访地址；
- 不读取 `events.db` 的原始事件行，只输出聚合计数；
- 不导出原始日志全文，只回读尾部有限行数。

即便如此，提交前还是建议自己扫一眼：内网网段、主机名、自定义路径这类信息，如果不想公开，直接在文本里改掉即可。

**请不要在 Issue 里直接贴未经脱敏的 `config.json`、完整日志文件或 `events.db`。**

## 八、提交 Issue

带上 6 件套，到 [仓库 Issues](https://github.com/wangbujiangwude/ipsense-fnos/issues/new/choose) 选「问题反馈（BUG）」模板，逐项填完提交。

如果只是想先确认「是不是我配置错了」，可以先对照第六节自查，再决定要不要发 Issue。
