# IP 动态感知 · 使用说明

## 一、打开应用

### 1.1.29 新增了什么

- **装完 skill 不用再手工配 SSH 了**：新用户在 agent 那边敲一句 `mh setup`，它会一步步
  把 NAS 地址、用户名、端口配好，自动生成一对专用密钥、把公钥装进 NAS、把私钥取回本机，
  最后自己验证一遍。想先看它会做什么，加 `--dry-run` 只演示、不改动任何文件。
- **授权照样看得见、收得回**：新授权会出现在提交单「密钥授权区」，指纹、公钥、时间、
  设备都列出来；不想要了点「撤销授权」即可，只删本应用那行和密钥副本，不碰你其它密钥。
- **封禁改走飞牛自带防火墙**：AI 按标注封禁时写在「设置 → 安全性 → 防火墙 → 入站规则」，
  永久封禁重启后依旧保持；「防护 → 封禁名单」里为空是正常的，不影响阻断。

### 1.1.28 新增了什么

- **密钥授权搬到右上角了**：点开「提交单」，右上角「关闭」左边多了一个「密钥授权」入口，旁边的小数字是生效中的授权数。默认不展开，点一下才弹出授权列表；再点一下、点弹层空白处、或按 ESC 都能收起。
- **不同缩放都显示得全**：以前密钥授权是四个标签下面的一整块，展开后会挤住下面的列表；浏览器缩放到 90% / 100% / 125% 时，列表和底部信息会被裁掉。现在它改成悬浮面板，不占弹层的高度，缩放多少列表都完整显示。
- **功能一个没少**：里面照样列出指纹、公钥前缀、授权时间、设备名、是否生效，以及「撤销授权」按钮；私钥内容依旧不显示。撤销仍只删本应用那行授权和设备上的私钥副本。

### 1.1.27 新增了什么

- **提交单里多了「密钥授权区」**：点开「提交单」，四个标签下面多了一行可展开的「密钥授权」。点开能看到 AI 用 SSH 建立的授权：指纹、公钥、授权时间、设备名、是否生效。你有权知道这些，私钥内容不会显示在这里，也不会出现在任何报告里。
- **随时可以收回授权**：每个生效中的授权都有「撤销授权」按钮。点一下，设备上的私钥副本和 `authorized_keys` 里本应用那一行都会被删掉，AI 立刻连不上；你自己的其它密钥不受影响。想让 AI 继续干活，重新授权一次即可。
- **AI 不再每步都来问你**：以前复制提示词发出去，AI 会先问「确认封多久」；现在直接按你写在标注里的话执行，只有拿不准的地方（比如要封内网 IP、标注自相矛盾、一次要封一大片）才会回来问。
- **封禁怎么落地**：AI 通过 SSH 登录 NAS，用 `fw` 在飞牛**原生防火墙**里加一条入站拒绝规则（`/usr/trim/etc/fw.conf`），「系统设置 → 安全性 → 防火墙 → 入站规则」里能看到；永久封禁、重启后依旧保持，随时可用 `fw unban` 撤销。软件本身还是不碰防火墙设置。注意「防护 → 封禁名单」是另一套登录防护，那里为空是正常的，不代表没封禁成功。
- **账号密码也能连**：以前 `mh` 只认密钥，很多环境配不通；现在支持账号密码 SSH，也新增了 `mh key status` / `mh key revoke` 让 AI 自己查授权状态。

### 1.1.26 新增了什么

- **画像里只剩输入框了**：IP 右边那一行原来有个蓝色的「保存并加入提交单」按钮，和点开输入框后弹出来的写标注窗口里的保存按钮是同一件事；而且 1.1.24 改成「点输入框弹窗」以后，那个按钮已经点了没反应。现在把它去掉，这一行只留输入框。
- **怎么写、怎么存没变**：点输入框 → 弹出写标注窗口 → 写要求或点现成的常用要求 → 点窗口里的「保存并加入提交单」。保存完窗口收起，输入框显示刚写的内容。
- **软件还是不碰防火墙**：这一条没变，永远只观测，处置完全交给外部 agent。

### 1.1.25 新增了什么


- **提交单分了四个区**：点开「提交单」，上面多出「待处理 / 已完成 / 待撤回 / 全部」四个标签，每个标签上有数字，一眼看清还有几条没办。
- **复制的话变短了**：以前复制一大段提示词，现在就一句「请读取工程中的 AI 标记，按标注逐项修改」，下面再单独给 AI 一个读取路径。规矩、边界、建议流程都写进了 skill，不用每次反复发。
- **AI 干完能看总结**：AI 处理完会把这条挪到「已完成」，点「查看 AI 总结」能看到它大概做了什么。
- **做错了能撤回**：「已完成」里每条都有「待撤回」，点一下就进「待撤回」区；再复制复原提示词发给 AI，它一键帮你复原。
- **「全部」留了完整台账**：所有区做过什么、谁做的、什么时候，都在「全部」里按流水列出来。
- **AI 统一用 `mh` 操作**：AI 读写提交单只能走 `mh` 这一条命令，不能碰你的页面和设置；旧回执一律作废，避免把过时指令当成已完成。
- **软件还是不碰防火墙**：这一条没变，永远只观测，处置完全交给外部 agent。

### 1.1.24 新增了什么

- **写标注改成弹窗了**：标注框变回一行、不占地方。点一下它，会弹出一个单独的大窗口，在里面慢慢写；写完点「保存并加入提交单」，窗口收起。
- **不想打字可以点现成的**：弹窗里准备了几个常用要求（比如「先观察 24 小时」「交给 agent 判断」），点一下就把这句话加进输入框，还能自己再改。
- **弹窗开关更柔和**：「提交单」「关于」「投喂入口」和写标注窗口，打开和关闭都是慢慢淡入淡出，不再硬生生闪出来。
- **软件还是不碰防火墙**：窗口里写的、点的，都只是文字要求，交给外部 agent 去看；应用永远不改防火墙设置。

### 1.1.23 新增了什么

- **输入框会变大了**：点一下「IP 来源画像」里的标注输入框，它会展开成一大块，写长一点的要求也能看全；点框外任意地方，它就缩回原位。
- **弹窗有动效了**：点「提交单」「关于」，或者关于页里的「投喂入口」，弹窗会轻轻弹出来，不再是一下子闪出来。
- **点保存不会跑偏**：放大状态下点「保存并加入提交单」，输入框不会突然缩回去，按钮位置不变，不会点空。（1.1.24 起改为弹窗填写，1.1.26 起画像里已无此按钮）
- **不喜欢动效也行**：系统里开了「减少动态效果」，这些动画会自动关掉。

### 1.1.22 新增了什么

- **给 IP 写备注**：点开「IP 来源画像」，IP 右边多了一个输入框。想让 agent 怎么处理这个 IP，直接写在里面保存，比如「先观察 24 小时，再决定要不要临时封 2 小时」。
- **提交单**：顶栏「关于」左边多了「提交单」按钮，带小红点数字。保存过的 IP 都会列在里面，可以逐条移出或清空。
- **一句话交给 agent**：提交单下面点「复制读取提示词」，把复制到的内容发给任意连着这台 NAS 的 agent（通过 SSH 或装在 NAS 本机都行），由它自己判断要不要动手。
- **软件还是不碰防火墙**：这一点写死了——软件永远不改防火墙设置，也不会替你封 IP。它只把证据和你的要求整理好交出去。

### 1.1.21 新增了什么

- **三张地图变一张**：以前页面上有三张地图（境外、境内、全球分布），现在合并成一张，右上角多了三个按钮，点一下就能切换想看的那张，不用再来回滚动。
- **记住你上次看的是哪张**：切到「全球分布」后关掉页面，下次打开还是「全球分布」；切换不会重新加载地图，也不丢已经看过的数据。
- **地图更大了**：合并后地图区域比原来更高，连线和气泡都更清楚，当前选中的按钮会亮起来。

### 1.1.20 新增了什么

- **记录表不刷屏了**：同一个 IP 在同一秒打开一个应用会发出一堆请求，以前表格里会一行行铺开、除了路径全都一样。现在这些请求合并成一行，只显示「正常访问 · GET 200」这样的动作，并在下面用一行小字标出属于哪个应用（例如 `/fnzerror`）、合并了几个请求。
- **路径去画像里看**：想看具体访问了哪些路径，点表格任意一行打开「IP 来源画像」，在「路径明细 · 高频路径」里能看到完整路径和访问次数，点一下路径就能复制。这里原本的「高频路径」和表格的路径列功能重复，现在分工清楚了。
- **数据没少**：合并只是显示方式，分页总数和导出的 CSV 仍是逐条原始记录。

### 1.1.19 新增了什么

- **投喂二维码单独弹出、更大了**：点「关于」里的【投喂入口】，二维码会以独立弹层弹出，不再挤在关于页里把页面撑出滚动条；图片放大到原来的两倍多，扫码更清楚。点弹层空白处、点「关闭」或按 ESC 都能收起，收起后关于页还在。

### 1.1.18 新增了什么

- **多了「关于」按钮**：顶栏「设置」左边。里面有简短使用说明、注意事项、开发者、投喂二维码、企鹅群，以及能点击跳转的 GitHub 项目主页。
- **在线校验会自动复制 IP**：点「在线校验」会先把 IP 复制到剪贴板再打开查询页，复制成功 / 失败都会提示；内嵌浏览器禁用剪贴板时会自动降级，仍可点「仅复制 IP」手动重试。
- **可以在软件里直接查**：点「站内查询」，应用会用自己的三家在线归属源核对这个 IP，把逐源结果和裁决直接显示在画像里，不用跳到外部网站。区县仍可能为空，查到后填进输入框点「保存区级信息」即可。
- **筛选范围会记住**：实时访问事件、IP 来源记录、时间范围和趋势图例的上次设定，下次打开应用会原样保留；搜索框内容不会保留。
- **端口有数了**：Nginx / Docker 的 `combined` 日志本来不记目标端口，现在会按「日志行尾端口 → 日志内端口字段 → 端口映射 → 同站来路」依次补录。到「设置 → 数据源」填一条 `日志路径=端口`（例如 `/usr/trim/nginx/logs/access.log=5666`），Docker 反代日志同样适用；鼠标停在端口上能看到这个数字是哪种来源。
- **「Web 未识别」有解释了**：点开「访问协议构成」卡片放大再点「Web 未识别」，会看到完整成因——日志里没有 scheme，不是软件坏了；设置里可指定整站协议或开启「按已知端口补协议」。

### 1.1.17 新增了什么

- **运行报错能一键导出了**：设置最底部点「导出运行报错（已脱敏）」，得到一份纯文本。里面有软件运行时真正报出来的错：页面 JS 异常、地图 SDK 没正常加载、资源加载失败、接口报错与超时，还带发生时间、当时的底图状态和顶部状态标。
- **不用复现也能查**：点「查看最近报错」直接在界面里翻最近 100 条；报错会自动记下来，关掉页面也不会丢。
- **两份文件怎么选**：「导出运行日志」是完整诊断包（服务端日志 + 状态 + 前端报错摘要）；「导出运行报错」只讲报错，最适合直接贴给 AI 定位「地图没加载 / 白屏 / 接口失败」。
- **隐私**：地图 KEY、令牌、口令、邮箱会被抹除，来访 IP 只留前两段，URL 只保留参数名不带参数值；精确经纬度、本机位置描述、私有目录也不再出现在诊断包里。
- **报错存哪**：`$TRIM_PKGVAR/runtime_errors.jsonl`，最多 500 条，不会占满 NAS 空间，也不写进 `events.db`。

### 1.1.16 新增了什么

- **真机上弧线正常显示了**：合规底图（腾讯 / 高德 / 百度 / 天地图）下两张地图的弧线全部恢复；跨日期变更线的长弧在地图两侧边缘分段连续，不再整层消失。
- **设置里的开关能点了**：「散点模式流动光点」等所有开关，点文字或滑块都能切换。
- **目标端口不再一律 5666**：Nginx 访问日志本身不记录目标端口，日志没写就显示「未记录」，不再拿软件自己的端口冒充。历史记录会在升级时自动订正。
- **离线库的重庆误判被固化修正**：`39.144.239.169` 之类被离线库判成重庆、在线多数派判成安徽合肥的 IP，裁决结果会记下来，以后断网或重新核验都不会再冒出重庆；地域分布里残留的假「重庆市」气泡也会清掉。
- **区级信息怎么补**：三家国际免费源和本地离线库都不返回区县。IP 画像里点「在线校验」会打开 `tool.hiofd.com/ip/` 并自动复制 IP，把查到的「区」（例如包河区）填进输入框保存即可，会回写该 IP 的全部历史记录。也可以在设置里填一个自己可用的区级 JSON 接口自动补全。该网站接口带反爬签名、不是公开 API，软件不会在后台自动爬取。

### 1.1.15 新增了什么

- **境外长弧线不再中断**：全球散点视图改为「以本机经度为中心」的连续窗口，跨国际日期变更线的长弧一笔画完；合规底图另生成世界副本折线，任意缩放位置都能看到完整弧线。
- **同省来源看得见了**：境内来源不再归并成一个「中国」气泡，地域分布按省细分；同省不同市的短弧也不再被近距阈值吞掉。省份名「安徽 / 安徽省」会自动归一，不会拆成两个重复气泡。
- **实时访问事件可按范围筛选**：卡片右上角新增「全部范围 / 境内 / 境外 / 内网 / 局域网设备」下拉，只影响这块实时列表，记录表与地图不变。
- **归属地显示到区级**：记录表、实时事件、IP 来源画像、整组画像、五卡下钻明细都会显示「省 / 市 / 区县」。在线源查不到区县时可以在 IP 画像里手工填写，保存后会回写该 IP 的历史记录。
- **新 IP 自动核验**：新出现的公网 IP 一入库就进后台核验队列，不再需要手动点「批量校验高频 IP」才会修正离线库的旧归属。
- **高德 KEY 报错更好懂**：无效 KEY / 未绑定 Web 端 / 域名白名单 / 未配 jscode 会分别给出原因，正确域名是 `webapi.amap.com`。
- **运行日志一键导出**：设置界面最底部，导出的 `.txt` 已自动脱敏，可直接贴到 Issue。

页面右上角可切换「近 1 小时 / 近 24 小时 / 近 7 天 / 近 30 天」；实时事件每 3 秒、地图与统计每 12 秒自动刷新，间隔都可在设置里改。

页面分区：

- 顶部四格：访问总量、境内来源、境外来源、扫描与异常次数。
- 「境外来源 · 全球视图」显示境外 IP，「境内来源 · 中国视图」显示中国境内来源，弧线一律汇聚到本机。**连线颜色代表连接频率**：按本图内各来源的访问次数分 5 档，低频青蓝 → 中频琥珀 / 橙 → 高频红，地图右下角有「连接频率 低 → 高」色阶图例。来源圆点与连线同色；与本机重合的高频来源不画弧，仍以红点标示。整条连线统一单色；境内按省份、境外按国家合并。
- 「实时访问事件」：最新来源、归属、判定与动作。
- 「访问频率与趋势」：可切换总量 / 境内 / 境外 / 扫描四条曲线，鼠标悬停看具体数值。
- 「访问统计与排名」（`1.1.2` 起）：紧跟在全球地图下面，顶部三格是访问次数 / 国家·地区 / 独立 IP 合计，下面「境内访问排名」按省级行政区、「境外访问排名」按国家或地区双榜并排；点任意条目可下钻该地区来源 IP 明细。全页只此一处排名。
- 「访问分析」五张小卡（`1.1.0` 起）：访问协议构成、来路、受访页、入口页、终端设备，全部由 fnOS Nginx combined 日志一次派生；`1.1.3` 起可点击卡片或卡内任一条目放大查看详细信息与来源 IP；`1.1.4` 起卡片内不再出现滚动条；`1.1.5` 起设置抽屉滚动稳定、文字不再抖动；`1.1.6` 起鼠标停在地图上滚轮也能滚动设置内容。
- 「全球 IP 来源分布」（`1.1.2` 起）：固定一张全宽世界地图，境内归并到「中国」、境外按国家 / 地区落点；气泡大小与颜色表示访问次数，点气泡可下钻该地区画像。不再有境内 / 全球切换，右侧也不再重复放统计与排名。
- 「IP 来源记录」：支持范围、判定、来源、协议筛选与搜索；点任意一行展开该 IP 的完整画像，含「归属核验 · 多源交叉」结果（地图圆点点击复用同一套画像）。

### 点击地图圆点打开 IP 来源画像

地图上的圆点都能点，鼠标移上去会变成手型。点击后弹出的**不是地图内小卡片**，而是和「IP 来源记录」点行一模一样的右侧「IP 来源画像」抽屉：

- 圆点只对应一个 IP：直接展示该 IP 的归属地、范围、坐标、累计访问、首次 / 末次、目标端口、来源通道、最近判定，以及高频路径与最近 20 条动作。

### 访问协议与五张分析卡（1.1.0）

记录表和「IP 来源画像」新增「访问协议」一列 / 一行。`1.1.0` 把**协议通道**和**行为判定**拆成两件事：

| 维度 | 取值 | 含义 |
|---|---|---|
| 协议 `proto` | `https` / `http` / `web` / `ssh` / `tcp` / `udp` / `icmp` | 请求走的什么通道 |
| 判定 `verdict` | 正常 / 扫描 / 攻击 / 敲门 | 这次行为是什么性质 |

所以「`https` 正常访问」和「`TCP` 恶意扫描爆破」可以同时看清：前者是协议，后者是判定。SSH 登录审计标 `ssh`，内核 / 路由器日志按 `PROTO=` 标 `tcp` / `udp` / `icmp`。

> **`web` = 「Web 未识别」，不是「不是 HTTPS」。** fnOS 的 Nginx combined 日志里 `$request` 只含 `HTTP/1.1`，没有 scheme，也拿不到可信的 `X-Forwarded-Proto`。应用延续「标置信度、不伪造」的原则：没有可靠信号就老实标「Web 未识别」，不会硬猜成 `https` 或 `http`。画像里会写明协议来源：设置页手动指定 / 同站来路推断 / 未识别。
>
> 如果你的反代统一走 HTTPS，打开「设置 → 数据来源 → `web_scheme_override`」填 `https` 即可全量覆盖；留空则保持不猜。**不需要改动 fnOS 系统 nginx 配置**（改了也会被系统升级覆盖）。

五张分析卡的口径：

| 卡片 | 统计口径 |
|---|---|
| 访问协议构成 | 按协议统计请求数、独立 IP 数，并区分协议 × 判定 |
| 来路 | 无 referer → 「直接输入网址 / 无来路」；同站 → 站内路径；外站 → 只显示域名，不外带完整 URL |
| 受访页 | 按去掉查询串的 path 聚合，避免 `?_=时间戳` 把榜单刷满 |
| 入口页 | 按 `IP + UA + 30 分钟桶` 划分会话，取每个会话的第一条请求作为落地页 |
| 终端设备 | UA 粗略归一为「浏览器 · 系统」，不做指纹、不回传任何隐私标识 |

静态资源（`.js` / `.css` / 图片等）仍照常入库，保证「访问总量」口径不变，只是**在受访页 / 入口页榜单里剔除**，避免榜单被资源请求占满。入口页是粗略会话，不是登录态会话；同一 IP 换 UA 或跨过 30 分钟会算作新会话。

### 顶部「连接失败」提示（1.1.7）

页面右上角的状态标现在分三档：

- **运行中 · N 路数据源**（绿）：本轮所有接口都正常。
- **部分数据异常**（琥珀）：有单个接口没响应，鼠标悬停能看到具体是哪一路（趋势 / 排名 / 状态 / 实时事件等），其余数据照常刷新，不会整页停更。
- **连接失败** / **归属库异常**（红）：连续两轮接口全部无响应，或内置 IP 归属库未就绪。

`1.1.7` 之前，3 秒一轮的轻量轮询与 12 秒一轮的重数据轮询都用 `Promise.all`：9 个接口里任意一个超时，整轮结果全丢，状态标直接变红「连接失败」，而且只有下一轮恰好数据有变化才会改回来——所以会出现「五张卡、趋势、实时事件都有数据，顶部却一直红着」的现象。真机实测在 26 万行事件下，`/api/status` 冷聚合要 4～8 秒，缓存 4 秒过期后 9 个接口并发排队最慢到 7.75 秒，已经贴近前端 15 秒超时线，磁盘稍忙就会触发。

现在缓存过期先返回上一份数据、后台单独重算，页面请求不再等冷聚合；单个接口失败也只影响自己那一块，一轮成功即自动恢复绿标。如果看到琥珀色「部分数据异常」，先悬停看是哪一路，再检查应用日志 `/var/log/apps/ipsense.log`；持续出现可在设置里把「事件刷新间隔」调大。

### 浮层外滚轮也能滚动（1.1.6）

`1.1.5` 修好设置界面「无法滑动」后发现还有一个死角：抽屉打开时，鼠标必须严格停在抽屉里面才能滚；一旦移到左侧地图上方，滚轮就像坏了，设置内容纹丝不动。原因是 `1.0.12` 起为了防地图误缩放，浮层外的滚轮事件被 `preventDefault()` 直接吞掉，既不缩放地图、也不滚任何内容。

`1.1.6` 把「吞掉」改成「重定向」：

- 浮层**内部**：滚轮仍走浏览器原生路径，触控板惯性、拖动滚动条与键盘翻页都不受影响。
- 浮层**外部**（地图、遮罩、主内容区）：滚轮量转交给当前浮层内可滚动容器，设置界面、IP 来源画像、五卡放大面板都会照常上下滑动。
- 放大面板按鼠标相对面板中线的左右位置，决定滚左侧条目列表还是右侧详情区；选中的容器压根不可滚时才回退到另一侧，不做「滚到底连锁」。
- 按行 / 按页滚动会做 `deltaMode` 换算，`scrollTop` 由浏览器钳制边界；地图滚轮缩放和页面滚动依旧收不到事件，关闭浮层后自动恢复。

> 仍然不会缩放地图：这是 `1.0.12` 起就定下的约束，目的是避免点开画像后误操作底图。若你希望浮层打开时地图也能滚轮缩放，那属于另一套交互，需要单独调整。

### 设置抽屉滚动与文字稳定性（1.1.5）

`1.1.4` 的滚动条方案在设置抽屉上引出两个问题，`1.1.5` 已修复：

- **文字抖动**：旧版鼠标移入抽屉时把 `scrollbar-width` 从 `none` 切成 `thin`，内容区宽度实测从 459px 变到 449px，抽屉里所有标签、输入框与说明文字随鼠标进出反复重排。现在槽宽恒定，`scrollbar-gutter:stable` 还会始终预留槽位，内容增减或滚动条显隐都不会改变宽度。
- **无法滑动**：设置抽屉是 flex 列布局，内容区默认 `min-height:auto` 不肯收缩，`overflow-y:auto` 便失去效果。现在设置抽屉、放大面板的条目列表与详情区都补了 `min-height:0`，内容再多也能正常上下滚动。
- 滚轮拦截改用父链遍历，不再依赖 `Element.closest`，部分内嵌浏览器也能正常滑动。
- 遮罩去掉全屏高斯模糊，改为不透明度更高的纯半透明；抽屉独立合成层，文字渲染更稳定。
- 滚动条改为恒定的 6px 极淡细条，鼠标悬停只加深颜色、不改变宽度；页面主滚动条仍只是隐藏外观，滚轮、触摸板与键盘滚动照常可用。

### 滚动条与卡片布局（1.1.4）

`1.1.4` 起五张分析卡里不再出现垂直和水平滚动条：

- 卡片按内容自然展开，小卡显示前 8 条、完整 30 条仍在放大面板，不再靠卡内滚动查看。

### 五张分析卡的放大与下钻（1.1.3）

`1.1.3` 起五张卡不再只是静态榜单，卡片和每一条记录都能点：

- **点卡片标题区或右上角 ⤢ 按钮**：卡片从原位平滑放大成一块大面板，左侧是完整条目列表（最多 30 项，比小卡里的 8 项更全），右侧是详情区。放大用的是位置与尺寸过渡，文字不会被拉伸变形；点 ✕、点面板外遮罩或按 `Esc` 会沿原路收回。
- **直接点小卡里的某一条**：一步到位，放大后立刻显示这一条目的详情，不用先展开再选。
- **详情区有什么**：四格统计（访问次数 / 独立 IP / 首次 / 末次）、口径说明、**来源 IP 明细**（IP、归属地、范围、访问次数、末次时间）与最近 20 条动作。五个维度共用同一份 `/api/web/breakdown`，后端按卡片上的「展示名」反查原始日志值，所以**卡片里的数字和详情里的次数一定对得上**。
- **继续点来源 IP**：会收起放大面板，打开与「IP 来源记录」点行完全相同的右侧「IP 来源画像」抽屉，可以看归属核验、协议构成、高频路径与逐条连接时间。
- 放大期间地图滚轮缩放同样被关闭（和 IP 画像抽屉一致），但面板内的列表仍可正常滚动；放大面板与画像抽屉不会同时叠在一起。

> 五个维度的口径各有差别，详情区会写明：协议构成统计全部来源（含 SSH / 内核事件），不限 Web；受访页按去查询串的路径聚合且剔除静态资源；入口页只统计每个会话的第一条请求；来路把无 referer 记为「直接输入网址 / 无来路」；终端设备只做「浏览器 · 系统」粗略归一。

### 全球 IP 来源分布 与 访问统计与排名（1.1.2）

`1.1.2` 把原来分散在三处的同一份地区访问数据合并成上下两块：

- **上面「全球 IP 来源分布」**：固定一张全宽世界地图，不需要切换。境内所有来源统一归并到「中国」一个点，境外按国家 / 地区落点，气泡大小与颜色表示访问次数。点气泡会打开该地区的来源 IP 画像抽屉。
- **下面「访问统计与排名」**：顶部三格汇总（访问次数 / 国家·地区 / 独立 IP 合计），下面是「境内访问排名」（按省级行政区）与「境外访问排名」（按国家或地区）双榜并排。点任意条目同样能下钻该地区来源 IP 明细。

之前「地域数量分布」右侧的排名条 + 汇总数字，与下方「境内 / 境外访问排名」内容重复，这一版已合并，全页只保留下面这一处排名；排名数据本身没有减少。

> **为什么是气泡，不是自绘省界 / 国界？** 这是合规要求。应用**不产出任何边界或区划轮廓数据**，后端 `/api/geodist`（默认 `scope=all`）只返回按国家 / 地区聚合的数字和内置中心点坐标；配置合规底图后在其上叠加数量气泡，未配置 key 时降级为只画经纬网、不绘国界的坐标散点示意。**国界与行政区划一律以官方合规底图为准**。中国香港、中国澳门、中国台湾统一计入中国。气泡大小与颜色只表达访问数量，不代表行政区划范围。

## 二、配置合规地图底图（重要）

应用**不内置任何地图密钥**。未配置时显示的是「坐标散点示意」——只按经纬度画点和弧线，
不绘制任何国界或海岸线，数据、趋势、排名、记录都照常可用。

`1.1.8` 起「设置 → 地图与位置 → 地图服务」预置四家合规底图，可随时切换：

| 服务商 | 密钥 | 申请入口 | 坐标系 |
|---|---|---|---|
| 腾讯地图 GL JS | `key` | 腾讯位置服务控制台 | GCJ-02 |
| 高德地图 JS API 2.0 | `key` | 高德开放平台控制台 | GCJ-02 |
| 百度地图 GL v1.0 | `ak` | 百度地图开放平台控制台 | BD-09（自动转换） |
| 天地图 4.0 | `tk` | 天地图开发平台 | CGCS2000 |

以腾讯为例：

1. 打开 [腾讯位置服务控制台](https://lbs.qq.com/dev/console/application/mine)，创建应用并添加 key，类型选「WebGL JavaScript GL」。
2. 在 key 的设置里配置 **Referer 域名白名单**，填你的飞牛访问域名或内网地址，避免被盗用。
3. 复制 key，回到应用「设置 → 地图与位置 → 地图服务」，选中「腾讯地图 GL JS」，在 `key` 输入框粘贴，点「保存配置」，**保存后立即生效，无需刷新页面**。
4. 页面顶部提示变为「底图由 腾讯地图 GL JS 提供」即生效；国界与行政区划以官方底图为准。

其它三家流程相同，密钥分别填到各自卡片下，切换不丢。也可点「+ 添加接口」配置自定义 SDK 地址与自己的 API 密钥，详见「地图服务切换与自定义接口（1.1.8）」。

> 中国香港、中国澳门、中国台湾均计入境内，不会作为国家或境外地区展示。
> 请勿把密钥写进公开仓库或截图外发。禁止接入 Google Maps / OpenStreetMap / Mapbox 等未获资质的地图来源。

### 填了 key 还是不显示地图？

打开「设置 → 底图诊断」，先看状态再逐项排查；页面顶部也会直接显示失败原因，并可用「重试底图」按钮重新加载。

| 检查项 | 说明 |
|---|---|
| 密钥类型 | 腾讯需勾「WebGL JavaScript GL」，高德建「Web端 (JS API)」Key，百度建「浏览器端」AK，天地图申请「浏览器端」tk |
| 域名 / Referer 白名单 | 必须包含当前访问地址，例如 `http://192.168.1.10:5666`；只填域名而用 IP 访问会被拒绝 |
| 网络可达 | 浏览器要能访问对应 SDK 域名（`map.qq.com` / `webapi.amap.com` / `api.map.baidu.com` / `api.tianditu.gov.cn`） |
| 配额 | 控制台查看当日调用量是否用尽 |
| 容器尺寸 | 诊断面板里两个地图容器尺寸若为 `0 × 0`，说明页面布局异常，可点「重试底图」 |
| 资源请求 | 「底图资源请求」若显示「N 个被拒」，基本可确定是白名单或配额，去控制台核对 |

以上任何一项失败都只影响底图：应用会自动回落到坐标散点示意，采集、趋势、排名与记录全部照常可用。

### 本机位置（出口 IP 定位）

地图上的「本机」点是所有访问弧线的终点。1.0.3 起不再预设任何城市，由你主动定位：

1. 打开「设置 → 地图与位置 → 本机位置」，点「自动定位本机」。
2. 应用取宽带出口 IP，识别 clash 等代理产生的第二个出口，再交叉取归属与经纬度，结果写入配置并立即刷新地图。
3. 面板同时显示在线结果与随包 `ip2region` 离线库的判定；两者不一致时以在线结果定位本机，其它来源 IP 的归属仍以离线库为准。

> 定位只在点击时发起一次对外请求，不会常驻联网；不点就完全不查。
> 本机位置记录的是**宽带出口 IP 的归属地**，不一定是设备物理所在地——运营商 IP 段常跨省分配。若想标注实际所在地，直接在「本机纬度 / 本机经度 / 本机标注」里手填即可，手动修改后来源会标记为「手动填写」。
> 定位结果保存在 `/vol1/@appdata/ipsense/config.json`，升级、重装均不丢失；页面只按坐标画点，国界与行政区划一律以腾讯地图合规底图为准。

### 弧线与性能（1.0.5 / 1.0.11 / 1.0.12）

弧线从来源点沿连线法向微微弯向「本机」，弯曲幅度与两点距离成比例：近距离几乎是直线，远距离才是长弧，不会在本机周围绕出回环。`1.0.11` 起每条弧整条统一单色、一次生成，不再拆成三段做明度渐隐；细线不遮挡底图地名。`1.0.12` 起改用三次贝塞尔曲线并按距离加密采样（24～64 段），两个控制点沿连线方向分布，端点切线贴合连线、中段圆润饱满，跨半球的超长弧也不再有肉眼可见的折角；腾讯地图连线端点改为圆头。弯曲幅度与旧版保持一致，只提升顺滑度。

连线的**色相**代表连接频率，整条线只有一个颜色：低频青蓝 → 中频琥珀 / 橙 → 高频红，共 5 档，右下角有色阶图例。**来源圆点与连线同色**，与本机距离过近的来源不画弧、但仍画一个按频率着色的圆点，高频来源不会因「只画点」而丢失频率信息。频率按当前地图内各来源访问次数的**相对高低**归一（弧线与近距点同池比较），因此切换「近 1 小时 / 近 30 天」时颜色仍会拉开，本图最频繁的那条始终是红色、最少的始终是青色；若所有来源次数相同，则统一落在中档。境内外区分仍靠各自的视图与标签，不再靠线色。

来源按行政区合并：**境内按省份、境外按国家**，同省几十个 IP 只画一条，坐标取组内加权平均值；与本机距离过近（小于 0.35°）的来源只画一个小灰点、不画弧，放大到市级也能看到本机周边有来源。默认每张地图最多画 16 条，超出的只计入统计。

打开「设置 → 地图与位置 → 弧线与性能」可以调整：

| 设置项 | 默认 | 说明 |
|---|---|---|
| 每张地图最多显示弧线 | 16 | 可填 5–60；设备性能有限时调到 10 左右最省 |
| 弧线弯曲幅度 | 0.12 | 可填 0.04–0.28，越大越弯；觉得太直就调大 |
| 散点模式流动光点 | 开 | 仅影响未配置 key 时的示意模式，关闭可省 CPU |
| 实时事件刷新间隔（秒） | 3 | 最小 2 秒 |
| 地图 / 统计刷新间隔（秒） | 12 | 最小 5 秒，调大可明显降低负载 |

改完点「保存配置」立即生效，不用刷新页面。页面切到后台会自动暂停轮询，切回来立刻补刷一次。
「设置 → 底图诊断」里能看到当前绘制条数、合并 / 近距 / 省略数量、重绘次数与最近一次重绘耗时；数据没变化时重绘次数不会增加，说明已跳过无谓渲染。

## 三、数据来源

打开「设置」，按需要勾选，保存后采集器自动重载。目前有 5 类事件来源 + 1 套归属校验源。

### 1) 本机日志（默认开启）

- SSH 认证：`/var/log/auth.log`
- Web 访问：`/usr/trim/nginx/logs/access.log`
- fnOS 结构化登录审计：`auth.log` 里的 `TRIMEVENT` JSON，`SshdLoginAuthFail` 判认证攻击、`SshdLoginSucc` 判正常登录、登出不入库
- SSH 轮转日志：`auth.log.1`、`auth.log.*.gz`，首次或点「回填历史日志」时读取，补回更早的登录审计轨迹（本机回环 `127.0.0.1` 的失败登录已在忽略列表过滤，不算外部攻击）
- 需要 root 读取，应用已按 root 运行。

### 2) 路由器日志（默认开启）

两种方式，任选其一或同时用：

- **Syslog 推送**：在路由器后台把系统日志 / 防火墙日志的远程服务器设为
  `飞牛内网IP:5514`（UDP）。常见路由器日志里的 `SRC=`、`DPT=`、`DROP` 关键字都能识别。
  端口可在设置里改，注意不要和其它服务冲突。
- **文件导入**：把导出的 `.log` / `.txt` 放进 `/vol1/@appdata/ipsense/inbox/`，
  应用每 5 秒扫描一次新文件。想重新导入同一份日志，换个新文件名即可。

### 3) 端口敲门（预留，默认未安装）

应用已预留 `knock` 数据源，但**不会替你修改防火墙**。启用步骤：

1. 在路由器把敲门端口序列（例如 7000 / 8000 / 9000）转发到飞牛。
2. 以 root 在飞牛上添加一条**只记录日志**的 nft 规则（不 drop、不 accept）：

   ```bash
   nft add table inet ipsense
   nft add chain inet ipsense knocks { type filter hook prerouting priority -150 \; }
   nft add rule inet ipsense knocks tcp dport { 7000, 8000, 9000 } log prefix "IPSENSE-KNOCK " flags tcp sequence
   ```

3. `mkdir -p /etc/ipsense && touch /etc/ipsense/knock.enabled`
4. 在应用「设置」里打开「端口敲门 · 内核日志」，保存。

应用会跟踪 `/var/log/kern.log`，把带 `IPSENSE-KNOCK` 且含 `SRC=` / `DPT=` 的行记为敲门事件。
诊断脚本：`/vol1/@appcenter/ipsense/scripts/enable_knock.sh`（只读，不改规则）。
回滚：`nft delete table inet ipsense`。

### 3b) 敲门网关请求日志（1.1.14，默认关闭）

如果设备上装的是应用中心的「敲门 knock Lite」（`fn-knock-lite`），用这一节把它接到 IP 动态感知里。它和上面的内核日志通道是**两回事**，不要打开「端口敲门 · 内核日志」去接它。

1. 先在敲门应用里打开日志：`系统设置 → 日志 → 启用网关请求日志`，保留周期至少 1 天。它默认**关闭**，也默认不记录 `127.0.0.1` 本机回环；被网关限流直接掐断的请求同样不会写进访问日志。**本应用不会替你打开这个开关。**
2. 确认日志目录：默认在网关运行目录的 `logs`，真机实测为 `/vol1/@appdata/fn-knock-lite/gateway/logs`。若你在敲门应用里改过「日志保存目录」，这里也要填同一个路径。
3. 在 IP 动态感知「设置 → 数据来源」打开 **「敲门网关 · 请求日志」**，填好目录与入口端口（Lite 版默认 `8999`），保存后采集器自动重载。
4. 从外网访问一次走敲门网关的服务，回到记录表把「来源」筛成「敲门网关」即可看到事件；汇总日志的 `3.1` 小节也会列出按动作分组的明细。

应用只读它按天落盘的 JSON 分片，按字段白名单提取客户端 IP、动作、Host / 路径、状态码与协议；字段缺失留空，协议无法确认标「未识别」，**不猜、不补齐**。动作分「认证通过 / 认证被拒 / WAF / 策略拦截 / 网关请求」四类，这只是网关记录的事实，不等于攻击定性。


### 4) 归属信息源 · 多源交叉校验（默认开启）

离线库对运营商网段重分配更新滞后，例如 `220.205.x.x` 网段曾被判到河北、天津、内蒙古、甘肃，
而多家在线权威源一致判为安徽合肥。开启后按 4 票多数派裁决：

| 票 | 数据源 | 说明 |
|---|---|---|
| 1 | `ip-api.com` | 中文，返回国家 / 省 / 市 / 运营商 / 经纬度 |
| 2 | `ip.sb` | 返回国家 / 省 / 市 / ASN |
| 3 | `ipinfo.io` | ISO 国家码 + `loc` 坐标 |
| 4 | 本地 `ip2region_v4.xdb` | 离线基础源，始终参与 |

- 裁决结果写入 `geo_cache`（默认 30 天有效）并回写历史事件，地图、排名与记录立即使用更准的归属。
- 三家在线源并行查询；单源失败或全部不可用时自动回退离线库，界面会标注置信度。
- 后台按 1.5 秒节流校验高频公网 IP；在「IP 来源画像」里点「立即在线核验」可单独复核某个 IP，
  区块里会逐个列出每个数据源的原始判定、裁决结果、置信度与核验时间。
- 设置页可关闭校验、调整有效期与批量校验数量，并查看各源命中次数与源间分歧数。
- 英文城市名（如 `Hefei`、`Guangzhou`）统一归一为中文，裁决后的地图坐标与最终省份保持一致，
  避免已改判的省份仍沿用旧库坐标把点位画到外省。
- 升级后会自动执行一次历史脏值订正；也可在设置页点「订正历史归属」手动重跑，
  清洗旧版本留下的英文国名、IPv6 省份与错位坐标。
- **出口 IP 的归属不等于设备物理位置**：运营商跨省地址池会让深圳宽带显示安徽网段，
  本机位置建议以手动填写为准。

### 5) 内网设备单独归类（默认开启）

`192.168.x`、`10.x`、`127.0.0.1` 等局域网访问会标为「局域网设备」，仍保留在记录表
（筛选「范围 → 局域网设备」可查），但不再以「无归属公网来源」污染地图、热点与境内外排名。
设置页可关闭该分流。

## 四、常用操作

| 想做什么 | 怎么做 |
|---|---|
| 看某个来源的 IP 与具体连接时间 | 直接点地图上的圆点，右侧「IP 来源画像」抽屉里逐条列出 |
| 只看某一种协议的记录 | 「IP 来源记录」→ 协议选 `HTTPS` / `HTTP` / `SSH` / `TCP` 等 |
| 让 Web 记录显示 `https` 而不是「Web 未识别」 | 设置 → `web_scheme_override` 填 `https`，保存后新记录生效 |
| 看最常被访问的页面 / 用户从哪进来 | 「访问分析」的「受访页」「来路」「入口页」三张卡片 |
| 看各省 / 各国的访问量 | 「访问统计与排名」双榜（境内按省、境外按国家），点条目下钻；地图看全球落点 |
| 点开画像后不想让地图跟着滚轮缩放 | 无需设置，`1.0.12` 起抽屉打开时自动关闭地图滚轮缩放，关闭后自动恢复 |
| 看哪条来源连接最频繁 | 看连线颜色：越偏红频率越高，对照地图右下角「连接频率」色阶图例 |
| 核对某个 IP 的归属地准不准 | 点开该 IP 的「IP 来源画像」→「归属核验 · 多源交叉」→「立即在线核验」 |
| 批量校正高频来源的归属 | 设置 → 「批量校验高频 IP」，后台按 1.5 秒间隔逐个复核 |
| 清洗旧版本遗留的归属脏值 | 设置 → 「订正历史归属」，清空无效省份、归一英文国名并重算错位坐标 |
| 补录更早的历史访问 | 设置 → 「回填历史日志」，后台执行约 10–60 秒后刷新页面（含轮转日志） |
| 只看局域网设备 | 「IP 来源记录」→ 范围选「局域网设备」 |
| 导出记录给别处分析 | 「IP 来源记录」右上角「导出 CSV」 |
| 改本机在地图上的位置 | 设置 → 「自动定位本机」，或手填本机纬度 / 经度 / 标注（未定位时为中国中心） |
| 曲线太多、机器有点卡 | 设置 → 「每张地图最多显示弧线」调小，或把地图刷新间隔调大 |
| 忽略某个内网 IP | 设置 → 忽略的 IP，逗号分隔 |
| 调整保留时长 | 设置 → 记录保留天数（默认 30 天） |
| 重载采集器 | 设置 → 「重载采集器」，不重启应用 |

## 五、常见问题

**x86 和 ARM 该装哪个安装包？**
`1.1.14` 起同时提供三个包：`ipsense_1.1.14_all.fpk`（通用，**推荐**，x86 与 ARM 都能装）、`_x86.fpk`（x86_64 专用）、`_arm.fpk`（aarch64 专用）。三个包的程序内容**完全相同**（纯 Python，无原生二进制），区别只在清单里 `platform` 一行；日常安装直接用 `all` 包即可，只有把应用按架构分发到第三方应用源 / 商店时才需要另外两个。按 fnOS 规范，`platform` 决定安装包适用于哪种设备架构，选错架构的包时换对应包重试即可。

**点开「IP 来源画像」一直停在加载中？**
`1.1.1` 已修复。真机上有的内网 IP 累积了近 20 万条访问，旧版画像要对全历史做 8 次聚合，约 3～4 秒甚至更久；现在改为按最近 3000 条动作一次性聚合，真机实测约 0.35 秒打开（原约 3.8 秒）。若请求真的失败或超时，抽屉会直接显示原因，不再无限等待。

**画像里的「统计口径」提示是什么意思？**
仅「累计访问 / 首次 · 末次」是该 IP 的全历史精确值；会话数、端口 / 路径去重数，以及协议构成、来路、高频路径、终端设备、最近动作等明细，都基于最近 3000 条动作。只有超过 3000 条的超高频 IP 才会出现这个提示，普通 IP 的画像与之前完全一致。

**应用启动是不是变快了？**
是的。`1.1.1` 起 socket 先创建，历史回填、在线校验队列和首屏数据预热都放到后台线程；首屏聚合在启动时预计算并缓存，页面第一次打开直接命中。数据最多滞后数秒，不影响实时采集。

**为什么数据偶尔不是「刚好这一秒」？**
首屏聚合结果带 4 秒短缓存，避免每次轮询都重扫 24 万行事件；需要立刻刷新时点页面上的刷新按钮，或等几秒自动更新。

**地图是空的 / 只有网格？**
说明没有配置地图 key，或 key 未通过校验。此时是坐标散点示意，本就不画国界；
配置 key 后会显示合规底图。若仍无点，说明该时间范围内没有带坐标的公网来源，可切到「近 7 天」或点「回填历史日志」。

**一条记录都没有？**
检查设置页「当前数据源状态」：日志文件是否存在、是否已读取。路由器日志需确认 UDP 5514 可达。

**应用中心显示 starting 但页面能打开？**
`install-fpk` 的安装钩子已直接启动服务，应用中心状态可能滞后；不影响使用。
稍等片刻状态会自动变为 `running`；若需要手动重来，在应用中心 Web UI 里停止再启动，或在 SSH 里执行 `appcenter-cli stop ipsense` 后再 `appcenter-cli start ipsense`（CLI 没有 `restart` 子命令）。

**连线颜色代表什么？为什么两张图都有红线？**
`1.0.11` 起线色只表示连接频率，5 档由冷到热：低频青蓝、中频琥珀 / 橙、高频红，右下角有「连接频率」色阶图例；来源圆点与连线同色，与本机重合的高频来源不画弧、仍以红点标示。境内外不再靠线色区分，改由各自的视图与标签区分。频率是**本图内相对值**，切换时间范围后同一条线颜色变化属正常现象；看绝对次数请用「境内 / 境外访问排名」。

**为什么以前一条线会分成几段颜色？**
`1.0.10` 及更早版本把每条弧拆成 3 段做「由浅到深汇聚本机」的渐隐尾迹，同一频率档里又分浅、标准、深三个明度，所以看起来像一条线被切成几段。这既不是断线，也不是频率沿线变化，而是旧版的方向感设计。`1.0.11` 起整条弧线统一单色，那段跳变已移除，颜色严格只代表连接频率。若仍看到旧效果，先刷新页面，并确认应用已升级到 `1.0.11`。

**点开 IP 信息后，滚轮还会缩放地图吗？**
不会。`1.0.12` 之前遮罩只能挡住鼠标点击，挡不住地图 SDK 自己的滚轮手势，所以点开画像后滚轮仍会缩放底图。现在抽屉一打开就关闭三张地图（含 `1.1.0` 的地域分布图）的滚轮缩放，抽屉内的滚轮原生滚动画像内容；`1.1.6` 起抽屉外的滚轮改成重定向，鼠标停在地图上滚轮也会滚动画像 / 设置内容，但不会缩放底图；关闭抽屉后自动恢复。若仍出现，先刷新页面确认已升级到 `1.0.12` 及以上。

**为什么很多 Web 记录显示「Web 未识别」？**
`1.1.0` 起协议一栏显示「Web 未识别」，意思是日志里没有可靠的 scheme 证据，**不是说这次访问不是 HTTPS**。fnOS 的 Nginx combined 日志 `$request` 只含 `HTTP/1.1`，不含 scheme，也拿不到可信的 `X-Forwarded-Proto`。应用不硬猜，只在画像里标注协议来源。若你的反代统一是 HTTPS，在设置 → `web_scheme_override` 填 `https` 即可覆盖；填了 `http` 同理。外部站点的 referer 不会被拿来猜协议。

**1.1.9 点「选择文件夹」没弹出飞牛的目录窗口？**
原生选择器由飞牛桌面 / `/app-auth` 授权页渲染，只在 fnOS 应用中心里打开应用时可用；用独立浏览器直连 `http://IP:端口` 时没有桌面父窗口，就不会弹。这时在「手动填写 NAS 绝对路径（兜底）」里填 `/vol1/1000/…`，再点「校验并保存路径」。另外确认应用已升级到 `1.1.9`，清单里 `micro_app = true` 且统一鉴权已开启。

**1.1.9 目录校验一直提示没有写入权限？**
应用对目录要有写权限：在「系统设置 → 应用 → IP 动态感知 → 访问权限」里授权该文件夹，或改用「我的文件」下的目录（原生选择器会顺带授权）。只允许 `/vol`、`/home`、`/mnt`、`/media` 下的普通数据目录，`/vol1/@...` 应用数据区和 `/etc`、`/usr` 等系统目录一律拒绝。

**1.1.9 这份日志会自动封禁可疑 IP 吗？**
不会。应用只观测、不修改防火墙、不封禁 IP、不自动处置。日志只是把已经观测到的事实整理成 AI 可读的 Markdown，末尾附分析与处置建议提示；AI 给出建议后请人工确认再执行。

**1.1.13 为什么之前选中文件夹还提示「已取消选择」？**
因为传给飞牛桌面桥的参数格式不对，`directory:true` 没生效，选择器按「选文件」模式打开，拿不到目录路径；应用又把空路径当成了取消。1.1.13 已修正参数并区分取消与失败。

**1.1.13 升级后需要重新选择一次文件夹吗？**
需要。之前的「已取消选择」没有写入任何配置，升级后请重新点一次「选择文件夹（飞牛原生）」，选中目录点「选择」即可自动回填；已保存过的保存位置不会被清空。

**1.1.13 选择失败时会提示什么？**
不再统一说「已取消选择」。真正取消才提示「已取消选择」；其它情况显示飞牛返回的具体原因，并提示「可手动填写 NAS 绝对路径」，你也可以在手填框里直接填路径再点「校验并保存路径」。

**1.1.12 为什么按钮在地图上方就点不动？**
地图 SDK 会注入 `z-index:1000` 的交互层，容器没有隔离时它会盖住顶栏与抽屉。1.1.12 已给地图容器加 `isolation:isolate` 并抬高 UI 浮层层级，按钮恢复可点。

**1.1.12 修复后地图还能拖动、点圆点吗？**
能。隔离只改变层级归属，地图 SDK 在自己的容器里仍是最高层；1.1.12 只调整了容器在页面里的层级顺序，地图拖动、缩放、点圆点看 IP 画像都不变。

**1.1.12 升级后需要重新配置地图 KEY 吗？**
不用。这次只改前端 CSS 层级，配置、数据源、汇总日志目录与已保存的地图密钥都在 `/vol1/@appdata/ipsense` 里，卸载重装不会丢。

**1.1.11 点「选择文件夹」还会新开一个窗口吗？**
不会。1.1.11 起走飞牛桌面桥，卡片直接在应用窗口内弹出；独立浏览器直连时降级为应用内嵌的原生授权页，同样不新开窗口。若你仍看到独立窗口，说明运行的还是 1.1.10 或更早版本。

**1.1.11 卡片是谁画的？**
飞牛原生的。目录树、左侧分组、新建文件夹和「取消 / 选择」都由飞牛桌面或 `/app-auth` 授权页渲染，应用只负责在窗口里把它显示出来并接收选中的路径，不自绘目录树、不伪造文件列表。

**1.1.11 选完目录后要刷新页面吗？**
不用。结果经同源回调页回传，应用校验 `state` 后自动走后端四层校验并保存，设置里的「保存位置」「目录状态」会自己刷新，汇总日志也会在后台立即生成一份。

**1.1.10 点「选择文件夹」还是没弹出卡片？**
先确认浏览器没有拦截弹出窗口（地址栏右侧的「已阻止弹出式窗口」），允许后重试；仍不行就在「手动填写 NAS 绝对路径（兜底）」里填 `/vol1/1000/…` 再点「校验并保存路径」。在 fnOS 应用中心里打开应用时体验最完整。

**1.1.10 选完目录后要刷新页面才生效吗？**
不用。父窗口会收到卡片回传的路径，自动走后端四层校验并保存，设置里的「保存位置」「目录状态」会自己刷新；汇总日志也会在后台立即生成一份。

**1.1.10 卡片里能新建文件夹吗？**
能。小卡片底部有「新建文件夹」，这是飞牛原生选择器自带的能力（`creatable=true`），新建后直接选中即可。

**1.1.8 切换地图服务商会丢之前填的 key 吗？**
不会。四家（含自定义接口）的密钥按服务商 id 分别存在 `map_keys` 里，切换只改 `map_provider`，另一家的密钥原样保留。旧版只有单个 `map_key` 的会自动作为「腾讯地图 GL JS」的密钥沿用。

**1.1.8 自定义接口为什么保存不了？**
SDK 地址必须以 `http(s)://` 开头且包含 `{key}` 占位符，接口 id 只能用小写字母 / 数字 / `-` / `_` 且不能与四家内置 id 重复；命中 Google / OpenStreetMap / Mapbox 等未获资质来源会按合规要求直接拒绝。百度引擎的 SDK 地址还需保留 `{callback}`。

**1.1.7 数据都正常，为什么顶部还显示「连接失败」？**
旧版一次瞬时网络抖动就会把整轮 9 个接口的结果丢掉并标红，且只有数据恰好变化时才改回来，所以红标会卡住。`1.1.7` 起改为逐接口独立容错与三级状态标，一轮成功即恢复绿标；单个接口异常只显示琥珀「部分数据异常」，悬停能看到具体接口名。若持续红灯，请确认应用进程在运行，并刷新页面后观察。

**1.1.6 设置界面打开后，鼠标停在地图上滚轮没反应？**
已修复。旧版把浮层外的滚轮事件直接吞掉（只防地图缩放，不滚动内容），所以鼠标一移到左侧地图上方，滚轮就像失灵。`1.1.6` 起这些滚轮量会转交给设置 / 画像 / 放大面板的滚动容器：鼠标停哪儿都能把当前浮层滚起来，地图与页面仍然不动。注意地图滚轮缩放依旧关闭，这是 `1.0.12` 起就有意保留的行为。

**1.1.5 设置界面之前为什么会抖，现在还会不会？**
不会了。旧版鼠标移入抽屉时会切换 `scrollbar-width`，内容区宽度瞬间少 10px，文字被迫重排，看起来就是「时不时抖一下」。现在滚动条槽宽恒定且始终预留，hover 只改颜色，实测跳变 `+0px`。同时补了 `min-height:0` 让抽屉能真正滚动，滚轮拦截也加了兼容兜底，内容多时可直接上下滑。

**1.1.4 去掉滚动条后，内容多的时候还能滚吗？**
能。隐藏的只是滚动条的外观，滚动能力完全保留：小卡本来就只放 8 条（完整列表在放大面板），不存在被截断的内容；放大面板、画像抽屉、实时事件与记录表仍可用滚轮、触摸板或键盘滚动（`1.1.5` 起改为恒定极淡细条，不再随悬停显隐）。页面主滚动条同样只是隐藏外观，长页面照常上下滚动。

**1.1.3 点开卡片放大会不会重新加载页面、把数据刷掉？**
不会。完整条目列表在首屏 `/api/web/overview` 里一次取回（30 条），放大只是换一种版式展示这份数据，不发新的列表请求；只有点某个条目时才会请求该条目的明细。放大与收回都是纯前端动画，不刷新页面，也不会打断 3 s 实时事件和 12 s 轮询。

**卡片上的数字和下钻详情里的次数为什么能对上？**
因为后端不是拿「卡片上显示的名字」直接查库——显示名是归一化后的（如「站内 · /app/ipsense」「Chrome · Windows」），一个名字可能对应多条原始日志值。下钻时用同一套归一化函数把展示名反查成原始键集合，再用同一个条件统计汇总、IP 明细与最近动作，所以合并项也能精确还原。入口页还额外按会话首条请求对齐口径。

**卡片数字和详情里的次数偶尔差 1～4 条，是算错了吗？**
不是口径错，是实时采集的时间窗口在滑动。卡片数字来自首屏 `/api/web/overview`（结果有 4 秒缓存），详情是点开条目那一刻单独查 `/api/web/breakdown`；两次请求各自按当时时刻计算「最近 24 小时」的起点 `now - 86400`。几次请求之间，24 小时前的老事件会移出窗口、同时又有新事件入库，于是几万条的量级上会出现 ±几条的差异，且详情通常略小于卡片。真机实测紧邻请求 3 轮差值为 `-2 / 0 / 0`，24h 边界 ±5 秒内确有 6 条事件会被切走。固定数据集下两者严格一致；切换时间范围重新加载后会重新对齐。这类差异不影响来源 IP 明细与行为判定。

**1.1.2 把排名合并后，原来的地域分布数据少了吗？**
没有少，只是不再重复显示。全球地图、三个汇总数字、境内 / 境外双榜用的是同一时间范围的同一批事件；地域分布右侧那个排名条与下方双榜内容重复，已合并到「访问统计与排名」。省份级明细仍在境内榜，国家级明细仍在境外榜，点击条目都能下钻到来源 IP。

**「全球 IP 来源分布」为什么是气泡，不是填色地图？**
合规要求。应用不产出任何国界 / 省界轮廓数据，后端只返回按国家 / 地区聚合的数字和内置中心点坐标；有腾讯地图 key 时在合规底图上叠加数量气泡，没 key 时退化为只画经纬网、不绘国界的坐标散点示意。气泡大小与颜色只表达访问数量，不代表行政区划范围；国界与行政区划一律以官方合规底图为准。

**「入口页」和「受访页」有什么区别？**
「受访页」是所有被请求的页面按去掉查询串的路径聚合；「入口页」只取每个会话的第一条请求。会话按 `IP + UA + 30 分钟桶` 粗略划分，所以入口页回答的是「用户第一次落在哪个页面」。两者都会剔除 `.js` / `.css` / 图片等静态资源，但这些请求仍计入顶部「访问总量」。

**升级到 1.1.0 会丢历史记录吗？**
不会。升级只做幂等补列（`ALTER TABLE ADD COLUMN`），不重建表；已入库的历史 Web 记录会用原来的原始日志行重新解析，按 `dedup` 精确补上协议、来路、UA 等字段，不会重复 INSERT。回填结果写入 `meta`，重复启动不会反复扫描。旧版留下的归属脏值仍按 `1.0.9` 起的订正逻辑处理。

**1.1.0 的端口敲门会自动改防火墙吗？**
不会。这一版只是把三张截图里的协议、来路 / 受访页 / 入口页、地域数量分布做完，端口敲门仍保持「只观测、默认不改防火墙」。序列还原、授信时间线、动态白名单属于后续路线图，即便将来提供也必须显式开启并带超时与回滚。

**曲线很多时页面卡？**
数据不变不会重绘地图，来源也会按行政区合并。若设备性能有限，在「设置 → 弧线与性能」把弧线上限调到 10 左右、地图刷新间隔调到 20–30 秒，或关闭散点模式流动光点。
可到「底图诊断」看「地图重绘」次数：正常空闲时应保持不变。

**境外排名里出现英文国家名？**
`1.0.8` 起已补齐常见 ISO 码与英文国名的中文归一，港澳台也统一标注；`1.0.9` 起升级时会自动订正此前已入库的历史记录。若仍有个别生僻地区保留原文，属数据源覆盖限制，可在设置页点「订正历史归属」重跑。

**回填历史日志后，攻击记录没怎么增加？**
复核过 `auth.log.1` 的 10113 条 `Failed password`，其中 10108 条来自 `127.0.0.1` 本机回环，`auth.log.2.gz` 的 1896 条同样全部来自本机。这些是本机服务自连失败，不是来自互联网的攻击，已在「忽略的 IP」里过滤，不入库是正确行为。轮转日志的价值在于补回更早的 fnOS 登录审计轨迹。

**同一省份的来源点，为什么有的画到了外省？**
旧版在裁决改判省份后仍沿用本地库的旧坐标。`1.0.9` 起坐标与最终省份强绑定，升级时也会重算历史错位坐标；如仍发现，可在设置页点「订正历史归属」。

**某个 IP 的归属地判得不准？**
在该 IP 的画像里点「立即在线核验」，用三家在线权威源 + 本地库 4 票多数派裁决，裁决结果会回写历史记录。若只有一家在线源可用，置信度会标为「低」，可稍后重试。

**为什么访问总量里大部分是内网？**
局域网设备（手机、电脑、Docker 网桥、本机健康检查）访问 fnOS Web 都会写进日志。`1.0.8` 起这类记录单独归类为「局域网设备」，不进入公网地图与排名；记录表可按范围筛选查看。

**开启在线校验会不会把日志传出去？**
只会把 IP 地址单独发给三家 IP 归属服务查询，不会上传访问日志、路径或用户名；可在设置里随时关闭，关闭后完全走离线库。

**装了端口敲门，为什么 IP 动态感知里一条敲门记录都没有？**
应用里预留的「端口敲门 · 内核日志」通道是给 `IPSENSE-KNOCK` 内核日志用的；应用中心的「敲门 knock Lite」写的是按天分片的结构化 JSON，两边格式不同。请改用 1.1.14 的「敲门网关 · 请求日志」通道。另外确认对方应用的 `系统设置 → 日志 → 网关请求日志` 已经开启，关闭状态下它自己不会产生任何访问日志。

**接入敲门网关日志后，应用会自动封禁攻击 IP 吗？**
不会。本应用只读取对方已经落盘的日志，做归属、地图、排名与汇总展示；不打开对方日志开关、不改对方配置、不改防火墙、不封禁 IP、不自动处置。授信与后续访问是否相关，请结合同一 IP 的时间线人工判断，或把汇总日志交给 AI 后由你确认再动手。

**为什么日志里看不到 `127.0.0.1` 的请求，或者少了几条？**
这是敲门应用自身的口径：`记录来自 127.0.0.1 本机回环的日志` 默认关闭，被网关反代限流直接断开的请求不写访问日志，异步队列拥塞时的丢弃也不会落盘，超出保留天数的分片会被清理。这些缺失属于对方日志策略，不是 IP 动态感知漏采。

**出问题了想反馈，需要准备什么？**
`1.1.15` 起不用再手动翻服务器：点「设置 → 最底部 → 运行日志一键导出」就能得到一份**已脱敏**的 `.txt`；应用打不开时改用 `sh tools/diag_bundle.sh` 生成 `ipsense-diag-*.tar.gz`。两者都会自动抹除地图 KEY、令牌、口令与完整来访 IP，不含原始事件行。把文件贴到仓库的「问题反馈（BUG）」模板，按「诊断 6 件套」逐项填完即可。完整 SOP 见 [排障指南](排障指南.md)。**请不要直接把 `config.json` 或 `events.db` 发到公开 Issue 里。**

## 六、数据与隐私

- IP 归属默认走随包内置的 `ip2region_v4.xdb`（纯离线）；开启「在线多源校验」后，仅把 IP 地址单独发给 `ip-api.com` / `ip.sb` / `ipinfo.io` 查询归属，**不上传访问日志、路径或用户名**，可随时在设置里关闭。
- `1.1.0` 起采集的 `referer`、`User-Agent`、请求路径只写入本机 SQLite 并在本地聚合，**不会发给任何第三方**；「来路」卡片对外站只显示域名、不外带完整 URL，「终端设备」只做「浏览器 · 系统」粗略归一，不做浏览器指纹、不回传任何隐私标识。
- 数据库在 `/vol1/@appdata/ipsense/events.db`，卸载应用不会自动删除，可手动清理。
- 应用日志在 `/var/log/apps/ipsense.log`。
- 应用以 root 运行，但只做读取、记录和展示，不修改系统防火墙、不封禁任何 IP。
- `1.1.14` 起的敲门网关通道同样只读：不替你打开对方日志开关、不修改 `fn-knock-lite` 的配置或目录、不写入它的日志，只读取它已经落盘的结构化 JSON 分片。
