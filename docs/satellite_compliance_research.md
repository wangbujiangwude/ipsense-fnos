## 1. 合规红线（来自 `geo-map-compliance-guard` 技能，不可放宽）

- **允许的数据源仅四家**：腾讯地图、高德地图（AMap）、百度地图、天地图（NASG）。
- **禁止**：Google Maps（含 Google Earth / Satellite）、Apple Maps、Bing 海外版（含 Bing Aerial）、OpenStreetMap 直连瓦片、Mapbox、Leaflet + OSM、Esri / ArcGIS Online World Imagery 等无境内资质或数据服务器在境外的来源。**这一禁止对"卫星影像"同样有效**——境外卫星影像不会因为没有国境线就变得合规。
- **绝不内置任何有效 API KEY**：一律用开放平台申请占位符，由用户自行申请填入；前端明文 KEY 需配 Referer / 域名白名单，商用应由后端代理鉴权。
- **坐标系**：默认 GCJ-02（火星坐标）。
- **领土表示红线**：国界、台湾、南海诸岛等必须符合国家标准，**禁止错绘、漏绘、错标**；不得标注军事禁区、涉密单位、未公开敏感坐标；批量点位须遵守个人信息保护，仅本机私有存储。

> 现状核对：`src/app/server/map_providers.py:18` 的 `ENGINES` 与 `MAP_PROVIDERS` 正好是这四家；`:81` `ALLOWED_HOSTS` 放行四家官方域名；`:89` `BLOCKED_HINTS` 明确拦截 google / apple / bing / openstreetmap / mapbox / leaflet / esri 等。文件头注释与 `src/LICENSE:35`「不绘制国界、海岸线或行政区划边界」方向一致。本调研**未改动**这些文件。

## 2. 法规依据（联网查证结果）

| 依据 | 要点 | 对「卫星底图」的含义 |
| --- | --- | --- |
| 《地图管理条例》第 15 条（中国政府网） | 国家实行地图审核制度；**向社会公开的地图应报送有审核权的测绘地理信息主管部门审核**（景区图、街区图等内容简单的地图除外）。 | 卫星影像作为可缩放、可浏览的底图在 Web 上公开展示，属于「地图 / 互联网地图」，落入审核范围，不因"是照片"被排除。 |
| 同条例第 21 条 | 核发审图号的条件包括：**「完整表示中华人民共和国疆域」**、**「国界、边界、历史疆界、行政区域界线或者范围、重要地理信息数据、地名等符合国家有关地图内容表示的规定」**、不含不得表示的内容。 | 审核看的是**疆域是否被正确、完整表达**，不是看"有没有画一根线"。「漏绘」本身就是不合规情形。 |
| 同条例第 22 条 | 经审核批准的地图，应在适当位置**显著标注审图号**。 | 审图号是公开展示的强制标注，不能隐藏、裁剪、去除。 |
| 同条例第 33 条 + 《测绘法》第 38 条 | 互联网地图服务单位向公众提供地理位置定位、上传标注、地图数据库开发等服务应**取得测绘资质**；服务提供者应**使用经依法审核批准的地图**。 | 资质与送审义务主要落在**地图数据生产 / 服务方（图商）**；应用方义务是「使用经审核批准的地图」，不得自行编制、篡改。 |
| 国家测绘局《关于加强互联网地图管理工作的通知》 | 增值服务（浏览 / 搜索 / 标注 / 嵌入 / 下载等）**必须使用经审核批准的互联网地图**；地图数据库服务器须设在境内；**互联网地图审图号有效期 2 年**，内容变化或到期前重新送审；未经审核批准的地图一律不得公开登载、传输。 | 应用把底图嵌入自家页面即属"引用 / 嵌入"，底图必须已审、带审图号、服务器在境内。 |
| 自然资源部「地图审核」申请材料说明 | 「利用自然资源主管部门**具有审图号的公益性地图**且未对国界、行政区域界线或范围、重要地理信息数据等进行编辑调整」的情形，可不提供测绘资质证书。 | 指向天地图这类公益性、自带审图号的底图，是合规链路里较"轻"的一条；但前提是**不编辑调整国界 / 界线**。 |
| 百度地图开放平台官方 FAQ | 明示其互联网地图服务测绘资质（甲测资质 1100930）、**地图审图号 GS(2021)4841（移动端）/ GS (2021) 6026（PC 端）**；「用户在遵守平台使用条款的前提下可放心使用」；**不可去掉版权 logo**。 | 实证：**审图号由合规图商的底图承载**，接入方调用官方 SDK 即可，无需自行编制地图、无需自行送审。 |

**实务共识**（多来源交叉）：测绘资质是给地图数据生产商的，不是给 App 开发者的；绝大多数应用的合规路径是「接入持甲级测绘资质的合规图商 + 遵守条款 + 不篡改底图 + 不添加未经审批的地理信息」。

## 3. 核心辨析：「卫星图没有国境线，所以不用避嫌」为什么不成立

这是用户提出的原始设想，逐条辨析如下（**重点在审图号 / 测绘资质 / 边界表示要求，而非有没有画国境线**）：

1. **审图号的义务对象是「地图」，不是「线条」。** 卫星影像是地图数据的一种表现形式；只要作为可交互底图在 Web 上向公众展示，就属于《地图管理条例》第 15 条「向社会公开的地图」和互联网地图管理范畴。「没有国境线」只是**视觉要素的缺失**，不改变其法律属性，也不触发豁免（豁免仅限景区图、街区图、地铁线路图等"内容简单的地图"）。

2. **审核条件恰好要求「完整表示疆域」，方向相反。** 第 21 条把「完整表示中华人民共和国疆域」「国界……符合国家有关地图内容表示的规定」列为**核发审图号的前提**。也就是说，合规要求的是**正确、完整表达**，而不是「不表达」。把「刻意不画国界」理解为「避嫌」，在合规上是把义务读反了：漏绘国界、漏绘台湾及南海诸岛，恰恰是审核不通过 / 被整改的典型问题。技能红线同样要求「禁止错绘、漏绘、错标」。

3. **测绘资质与审图号由合规链路承担，不因"应用自己没画边界"而消失。** 应用方确实通常**不需要自己申请测绘资质、不需要自己送审**——但那是因为「底图用的是图商已审核、带审图号的合法地图」，而不是因为「应用没画线」。合规来源是**数据源合法 + 完整正确表达 + 显著标注审图号**三件事，缺一不可。若为了"避嫌"去自行裁剪边界、隐藏审图号 / 版权、或改用无资质影像源，反而切断了这条合规链路。

4. **边界表示不能靠"隐藏注记 / 边界"来规避。** 技能明确要求领土特征符合国家标准、禁止错绘错标；正确做法是**「边界一律以官方底图为准」**（`map_providers.py` 文件头已是这个口径），由官方底图负责正确表达，应用不在其上自绘、不改绘。腾讯卫星 `features:['base']` 这类"只显示影像、不叠注记 / 路网"的能力是**视觉选项**，不是合规豁免开关。

5. **卫星影像不是更宽松，而是更严格。** 卫星 / 遥感影像涉及分辨率、保密技术处理、涉密坐标、军事禁区等额外约束；第三方行业资料明确提示「灰度图、**卫星图、地形图在合规要求上比普通矢量图更严格**，做对公展示的项目发布前最好跟当地测绘主管部门确认数据合规性」。因此「换卫星图反而更省事」与实务相反。

6. **「避嫌」这个前提本身不成立。** 合规目标不是"避开敏感线"，而是"用合法来源、正确完整表达、标注审图号、不泄露涉密信息"。一个不带国境线的**境外**卫星源（Google / Bing / Esri）依然是**明确违规**源；一个不带国境线的**境内合规**卫星底图依然**必须**带审图号、保留版权、不得篡改。线画不画，都不是判定变量。

> **结论：该说法不成立，且若据此实施（例如为了"没国境线"而改接境外卫星瓦片、或裁剪掉底图审图号 / 版权）会直接违反白名单与审图号要求。**

## 5. 本项目的明确结论

### 5.1 能否合法接入
**可以。** 前提是只接第 4 节四家之一的官方卫星底图，并完成第 6 节前置条件。这与现有 `map_providers.py` 白名单、`app.js` 四家 SDK 统一包装、`LICENSE` 边界口径**不冲突**——只是把"有 KEY 路径"的底图从矢量扩展为「矢量 / 卫星可切换」，白名单与 KEY 机制可原样复用。

### 5.2 推荐：腾讯地图 GL JS 卫星底图
理由（均为只读核对所得的项目现状）：
- 项目**默认引擎就是腾讯**（技能亦规定未指定时默认腾讯），`app.js:1094` 已内置 `https://map.qq.com/api/gljs?v=1.exp&key={key}`；
- `app.js:1085` 起已把四家 SDK 统一包装成「形状与 `TMap.*` 一致」的对象，新增卫星 baseMap 切换属渲染层增量，改动最小；
- `map_providers.py:82` `ALLOWED_HOSTS` 已放行 `map.qq.com` / `lbs.qq.com` / `gtimg.com` / `qq.com`，无需动白名单；
- **坐标系一致**：腾讯 GCJ-02 与 `app.js:1170` 「应用内坐标恒为 GCJ-02」完全对齐，不需要像天地图那样做 CGCS2000 换算、也不像百度要 BD-09 转换；
- `setBaseMap({type:'satellite', features:['base']})` 能给出**纯影像、不带注记 / 路网 / 轮廓**的视觉，正好回应用户「不用轮廓图」的诉求——但请在产品表述里把它写成「边界以官方合规底图为准、不叠注记」，**不要**写成「没国境线所以合规」。

**备选**：
- **天地图影像**：若坚持要「公开瓦片 / 公益性审图号 / 数据自持感更强」，它最"透明"；代价是 CGCS2000↔GCJ-02 换算、实名 + 配额 + 白名单、以及 `BLOCKED_HINTS` 含 `leaflet` / `mapbox` / `carto` 等第三方瓦片容器关键词——若用 Leaflet / MapLibre 之类容器加载天地图瓦片会命中拦截，须走天地图官方 JS API 4.0 或后续单独评估白名单判断（本次不改代码）。
- **高德 / 百度卫星图层**：可行，但需分别申请 Key、处理百度 BD-09、且百度官方明确不可去版权 logo。

### 5.3 与现状的兼容性提示（只读观察，本次不改）
- `MAP_PROVIDERS` 目前是**矢量 SDK 模板**；卫星底图需在 SDK 初始化后追加 `setBaseMap` / 图层切换，属前端渲染层，不动 `compliance_of()` / `sdk_url()` / `validate_custom()` 的合规判定。
- `LICENSE:35`「不绘制国界、海岸线或行政区划边界」与 `map_providers.py:10`「边界一律以官方底图为准」是**正确且应保留**的口径；需避免把它误读为「因此可避嫌 / 因此豁免审图号」。合规来自官方底图已审核，不来自应用没画线。
- **无 KEY 的 Canvas 2D 降级路径**（`app.js:798–799`、`drawGeoCanvas()`）应继续「不绘任何边界」的散点示意，不因引入卫星图而改变；卫星图只作为「有 KEY」路径的底图选项。
- 技能默认场景的 `_TMapSecurityConfig` 代理模式（前端零 KEY）适用于 WorkBuddy 生成 HTML 的场景；本项目是 fnOS 原生应用、由用户在设置页自填 Key，应沿用现有 `key_configured()` / 占位符机制，不引入第二套鉴权。

## 6. 接入卫星底图的合规前置清单（Checklist）

### 必须（缺一不可）
- [ ] 仅使用**白名单四家之一**，且通过其**官方 SDK / 官方 API** 调用；卫星瓦片只允许来自四家官方域名。
- [ ] 用户自行到对应开放平台申请**浏览器端 / Web 端 Key**，并配置 **Referer / 域名白名单**；应用与本文**绝不内置任何有效 KEY**（沿用 `MAP_KEY_PLACEHOLDER` / `key_configured()` 占位符机制）。
- [ ] **保留服务商版权信息、审图号标注**，不隐藏、不裁剪、不去除水印（百度 FAQ 明确不可去 logo；第 22 条要求显著标注审图号）。
- [ ] **不篡改底图瓦片、不自绘 / 不改动国界、海岸线、行政区划边界**；边界一律以官方底图为准；不在底图上叠加未经审批的地理信息。
- [ ] 叠加层只放**应用自有数据**（IP 散点 / 连线），不标注军事禁区、涉密单位、未公开敏感坐标；批量点位遵守个人信息保护、仅本机私有存储（技能 Pre-Output 自检项）。
- [ ] **坐标系按引擎转换**：腾讯 / 高德 GCJ-02、百度 BD-09（自动转）、天地图 CGCS2000，复用 `app.js:1170` 现有转换层，避免偏移。
- [ ] 遵守服务条款与调用配额；**审图号有效期 2 年**，关注服务商底图内容变更 / 重新送审公告。
- [ ] 地图数据服务器在境内（由四家官方服务保证，不自建境外代理、不缓存转发境外瓦片）。

### 建议
- [ ] 若**公开发布 / 商用**：取得图商**商业授权**（第三方资料提示各家基础版约 5 万/年，仅作线索，**须自行向平台核实，不作为报价依据**）。
- [ ] 对公展示前，就**卫星 / 影像底图**数据合规性向当地测绘主管部门确认（第 3 节第 5 点：卫星图要求更严）。
- [ ] 设置页为「卫星底图」单独标注合规来源与审图号归属，沿用 `compliance_of()` 的 `allowed / custom` 标记。
- [ ] 产品 / 文档表述修正：把「不画国界 = 避嫌」改为「**边界以官方合规底图为准、应用不自行绘制**」。
- [ ] 前端 KEY 明文风险：个人使用配 Referer 白名单；若后续商用，考虑后端代理鉴权。

### 禁止
- [ ] 借「卫星图」之名引入任何**境外影像源**或其镜像 / 第三方瓦片 CDN。
- [ ] 缓存、离线分发、二次加工卫星瓦片；把地图数据服务器放到境外。
- [ ] 去除 / 遮挡审图号、版权、水印；以「隐藏边界 / 不画国界」作为规避审核或规避正确表示疆域的手段。
- [ ] 在无 KEY 的 Canvas 降级路径上自行绘制任何边界。

## 7. 必须让用户补充 / 确认的信息
1. 使用场景是**个人 / 内网自用**，还是**公开发布 / 商用**（决定是否需要商业授权与主管部门确认）。
2. 目标视觉：卫星底图是否需要**地名注记 / 路网**（决定 `features:['base']` 纯影像还是叠加 RoadNet）。
3. 是否已有**腾讯位置服务 Key** 且勾选「WebGL JavaScript GL」；若倾向天地图 / 高德 / 百度，是否有对应 Key。
4. 若倾向天地图：能否接受 **CGCS2000 坐标换算 + 日配额 + 实名认证**。
5. 是否有「对公展示 / 上架应用市场」计划（涉及图商授权证书提交）。
